02 / The journeys

More than CRUD.

The learning value lives in the boundaries: authoritative pricing, concurrency-safe availability, durable events, provider callbacks, scoped permissions, and recoverable failure.

  1. 01

    Search live inventory

    Booking asks Hotel for eligible rooms and rates, then combines them with reservations and active holds. Guests see room types, never internal room numbers.

    Public web → Gateway → Booking ↔ Hotel
  2. 02

    Commit the booking safely

    Availability is revalidated, the price is frozen, a physical room is assigned, and the reservation and outbox event commit in one transaction.

    PostgreSQL → Outbox → Kafka
  3. 03

    Complete provider-hosted payment

    Stripe Checkout handles cards, MB WAY, and Multibanco. Signed, idempotent webhooks—not the browser redirect—become the source of truth for payment state.

    Booking ↔ Stripe → Webhook
  4. 04

    Deliver and recover

    Notification consumes events, records delivery attempts, retries SMTP failures with backoff, and routes poison messages to a dead-letter topic.

    Kafka → Notification → SMTP

03 / The architecture

Separate ownership.
Explicit communication.

Each business service owns its schema. Synchronous calls answer immediate questions; Kafka and transactional outboxes carry work that must survive the original request.

API Gateway

Routes every client request, propagates correlation IDs, applies Redis-backed rate limits, and isolates downstream failures with timeouts and circuit breakers.

04 / Production-minded behavior

Failure is part of the design.

This remains a learning project, but the failure modes are treated seriously: bounded waiting, protected resources, durable work, and enough telemetry to understand what happened.

↯

Circuit breakers

Independent breakers stop repeated calls to unhealthy services, Stripe, and SMTP while controlled probes test recovery.

║

Bulkheads

Concurrency limits prevent slow external providers from consuming every request or notification thread.

◎

Safe retries

Only idempotent reads receive synchronous retries. Payments use stable idempotency keys; email retries are persisted.

⌁

Observable flows

Correlation IDs, Actuator, Prometheus, and Grafana expose request, circuit, retry, and bulkhead behavior.

Spring services→Actuator metrics→Prometheus→Grafana
